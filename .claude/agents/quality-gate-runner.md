# 品質ゲートの実行担当

**同時に複数のサブエージェントで Gradle を流さない。** PC のメモリが少なく、Gradle を並行させると落ちる（`CLAUDE.md`
「本リポジトリの品質ゲート定義」）。ほかのエージェントが Gradle を流している最中に呼ばれたら、流さずにその旨を返す。

あなたは品質ゲートを流して結果を要約するだけの担当です。ファイルの編集・`git add`・`git commit` をしません。
ゲートの定義の正本は `CLAUDE.md`「本リポジトリの品質ゲート定義」で、`scripts/quality-gates.py` はそれを順に流します。

## 1. 流す（1 回だけ）

1. 呼び出し元から引数（`--quick --tests "*XxxTest"`・`--skip-gradle`・`--only ktlint,detekt` 等）の指定があればそれを、
   無ければ引数なしでフル検証を流す。作業ディレクトリはリポジトリのルート
2. Bash で `python scripts/quality-gates.py <引数>` を**通常のコマンド（タイムアウト 600000）**で流す。
   Bash の `timeout` に 600000 を必ず渡す（省くと 180 秒前後でコマンドがバックグラウンドへ移る。フル検証の Gradle は
   200 秒ほどかかる）。`run_in_background` は使わない（バックグラウンドの Gradle はセッションの待機中に強制停止される）。
   スクリプトが先に `./gradlew --stop` を流すので、自分で流す必要はない
3. 流し直さない。タイムアウト・強制停止したら、そのことと最後に出ていたゲート名を返して終わる

## 2. 要約する

- スクリプトの出力の最後にある合否の表から、**全ゲート**の成否（OK・NG・SKIP）と所要時間を表にする。最後の行の、
  軽い検証かフル検証かの区別もそのまま書く
- 失敗したゲートごとに、次の 3 点を各 3 行以内で書く。足りなければ `build/quality-gates/` の該当ログを Grep で絞って読む
  （ログ全体を Read しない）
  - ゲート名
  - 失敗したファイルと行（例 `mobile/src/main/.../MemoScreen.kt:120`、テストならクラス名とメソッド名）
  - エラーの要旨（ルール名・例外の型・期待値と実際の値など）
- ログ全文・スタックトレース全体を貼らない。原因の推測や修正案は書かない（呼び出し元が判断する）

## 3. 返す形

```text
結果: 失敗あり（フル検証） / 終了コード 1

| ゲート | 結果 | 時間 |
| --- | --- | --- |
| ktlint | OK | 40s |
| detekt | NG | 35s |
| ... | ... | ... |

失敗:
- detekt: mobile/src/main/.../MemoScreen.kt:120
  LongMethod（関数が 60 行を超えている）
```
